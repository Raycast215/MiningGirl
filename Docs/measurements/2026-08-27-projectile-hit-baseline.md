
**1.0 미만이 0발**이므로, 판정 반경 안에 들어간 발은 예외 없이 전부 명중

## 이 값에서 읽어낸 것

### 살아 있는데 놓침 — MoveSpeed에 비례합니다

```
1.6 → 0.0%   2.0 → 0.7%   2.8 → 9.4%   3.0 → 14.0%   5.2 → 41.4%
```

발사체는 유도하지 않고 발사 순간 방향으로만 날아갑니다(1차 확정 사양).
조준선이 수직이 아니라 비스듬하므로, 수직으로 내려오는 몬스터는 그 선에서
옆으로 벗어납니다.

```
빗나가는 거리 ≈ 몬스터 속도 × (거리 ÷ 탄속) × 조준선 기울기
```

실제 손잡이는 순수 속도가 아니라 **속도 ÷ 판정 반경**입니다.
이 값의 순위가 실측 순위와 정확히 일치합니다.

```
심층의 것 1.67 < 바위게 2.13 < 갱도지키 2.97 < 광충 3.85 < 날벌레 6.05
```

같은 속도라도 작은 몬스터가 더 잘 피합니다. 광충(3.0)이 갱도지키(2.8)보다
더 잘 피하는 것이 그 예입니다 — 판정 반경이 0.78 대 0.94입니다.

### 대상 소실 — 속도와 무관합니다

```
광충 36.3%   바위게 31.3%   갱도지키 23.4%   날벌레 12.5%   심층의 것 0.0%
```

세 스킬이 전부 같은 "가장 가까운 적"을 봅니다. 이미 날아가는 발의 피해량을
아무도 세지 않으므로, 한 마리에 필요한 것보다 많은 발이 겹쳐 나갑니다.
앞선 발이 죽이면 뒤따르던 발은 빈자리로 날아갑니다.

발사체 수를 올리는 강화가 이것을 배로 늘립니다.

날벌레의 대상 소실이 가장 낮은 것도 같은 이유입니다 — 잘 피해서 한 발로
죽지 않으니 겹쳐 쏴도 낭비가 덜 됩니다.

## 수정 후 다시 잴 때

같은 항목으로 재야 비교가 됩니다. 계측은 `Projectile`의 `#if UNITY_EDITOR`
블록에 그대로 두었습니다.

```
Projectile.DebugResetCounters()   재기 전에 호출
DebugFiredBy / DebugHitTargetBy / DebugHitOtherBy
DebugMissGoneBy / DebugMissNearBy / DebugMissWideBy
DebugMissClosest                  빗나간 발의 최근접 거리 ÷ 판정 반경
```

**확인할 것 두 가지**

1. 대상 소실 26.5%가 실제로 줄었는가. 거의 그대로면 원인 분석이 틀린 것이므로 PM에 알립니다
2. "아슬아슬"이 어느 종에 몰리는가. 남는 것이 순수한 명중 문제입니다
